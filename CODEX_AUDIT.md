**Сценарий.** Агент изменяет открытый проект. Окно начинает перечитывание. Пока идёт await чтения, пользователь переименовывает проект или меняет монтаж. Чтение завершается раньше задержки автосохранения в 500 мс.

[ProjectSaveCoordinator.swift:76](</Users/alex/Documents/Вайбкодинг/Программы macos/Монтажка/Sources/Montazhka/Engine/ProjectSaveCoordinator.swift:76>) сохраняет в задаче старый снимок project. adopt на строке 56 меняет knownRevision и lineage, но не связывает их со снимком, поставленным в очередь раньше. **Доказательство.** [FinalExport.swift:101](</Users/alex/Documents/Вайбкодинг/Программы macos/Монтажка/Sources/Montazhka/Engine/FinalExport.swift:101>) заранее записывает в MP4 pendingDigest новых субтитров. Строки 108–109 устанавливают видео раньше SRT. При отказе SRT на строке 285 старый файл остаётся. На следующем экспорте ownedDigest на строках 217–222 сравнивает его старое содержимое с новым hash из MP4, получает nil и на строке 228 считает собственный файл чужим. Он больше не обновляется штатно.

**Фактическая проверка.** [FinalExportTests.swift:205](</Users/alex/Documents/Вайбкодинг/Программы macos/Монтажка/Tests/MontazhkaTests/FinalExportTests.swift:205>) проверяет сохранение старого SRT после сбоя и прошёл. Следующий повторный экспорт в этом тесте отсутствует; его результат выведен из указанной проверки hash.

**Предлагаемый фикс.** Сохранять признак владения предыдущими подтверждёнными субтитрами до успешной установки новой пары либо согласовать замену MP4/SRT с восстановлением. При этом сохранить защиту действительно чужих и вручную изменённых субтитров.

## 16. Мелочь — неверный тип MCP-поля превращается в другое намерение

**Сценарий.** Агент передаёт removePauses строкой "false" вместо boolean false или cuts объектом вместо массива.

**Доказательство.** [AgentCommand.swift:452](</Users/alex/Documents/Вайбкодинг/Программы macos/Монтажка/Sources/Montazhka/Agent/AgentCommand.swift:452>) использует arguments["cuts"]?.arrayValue ?? [], поэтому неверный тип означает отсутствие резов. На строке 467 boolValue ?? true превращает строковый "false" в включённое удаление пауз. Сходный fallback есть у enhanceVoice. Декларация JSON Schema не заменяет проверки в обработчике: используемые SDK getters возвращают nil при несовпадении типа.

**Фактическая проверка.** Подтверждено кодом обработчика и getters SDK. Неверные обязательные sourcePaths/UUID отдельно проверены через работающий MCP и корректно отклонены; это не доказывает валидацию перечисленных необязательных полей. Реальный монтаж с заведомо неверным boolean не запускался.

**Предлагаемый фикс.** Различать отсутствующее поле и присутствующее поле неверного типа. Значения по умолчанию применять только при отсутствии; для неверного типа возвращать INVALID_REQUEST до старта worker.

## Падения, главный поток и длинные записи: что не стало находкой

В проверенных путях массивные обращения сопоставлены с проверками диапазонов. Доказанного пользовательского сценария падения от force unwrap или выхода за границы массива не найдено; служебные константы и распаковки после guard не записаны как ошибки. Основной подтверждённый риск потоков — работа с AVAssetReader в №1. Управление окнами сосредоточено на MainActor; логическая гонка через await в №2 возможна и без обращения к SwiftUI с фонового потока.

Не обнаружено доказанного постоянного цикла удержания, из-за которого весь видеоматериал оставался бы в памяти после закрытия. Это результат статического просмотра, **не** заключение Instruments/Leaks: профиль памяти долгой GUI-сессии не снимался. Продолжение ненужной фоновой работы отдельно отражено в №13.

Полезные существующие ограничения:

- Waveform хранит 100 Float в секунду — около 1,37 MiB на час; есть NSCache на 64 MiB, дедупликация и два декода на хранилище. Сам цикл не хранит весь PCM. Ошибки завершения и отмены остаются в №6 и №13.
- VoiceEnhancer/MusicEQ и LoudnessMeter/Normalizer обрабатывают аудио порциями. CompositionBuilder загружает каждый исходник один раз и ограничивает параллельную подготовку.
- Локальный FluidAudio 0.15.5 включает потоковый путь для длинного URL-входа: конвертация порциями в файл и memory mapping. Загрузка всего часового PCM в единый Swift-массив на этом пути не подтверждена.
- FaceTrackStore ограничивает изображение 640×640; ShortsCutService делит длинную расшифровку на окна и ограничивает параллельные AI-запросы.

**Предположение, требующее измерения:** [EditorController.swift:1135](</Users/alex/Documents/Вайбкодинг/Программы macos/Монтажка/Sources/Montazhka/Engine/EditorController.swift:1135>) раз в секунду вызывает синхронную проверку ревизии через [ProjectSaveCoordinator.swift:71](</Users/alex/Documents/Вайбкодинг/Программы macos/Монтажка/Sources/Montazhka/Engine/ProjectSaveCoordinator.swift:71>). Чтение/хеширование крупного проектного JSON может задерживать главный поток. Реальную задержку интерфейса на проекте с тысячами клипов не измерял, поэтому это не включено в таблицу подтверждённых дефектов. Перед переносом проверки на фоновую очередь нужно сохранить атомарное сопоставление данных и ревизии.
