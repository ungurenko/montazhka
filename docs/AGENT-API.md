# 🎬 Montazhka Agent API v1

## Быстрый выбор

1. Вызвать `montazhka_doctor`.
2. Для обычного разговорного ролика выбрать `clean-speech`.
3. Для более плотного темпа выбрать `dynamic`.
4. Для шортсов и Reels выбрать моменты самому, согласовать их с пользователем и вызвать `montazhka_make_shorts` (раздел «Шортсы и Reels»).
5. Читать состояние долгой задачи через `montazhka_get_job waitSeconds=25` — вызов сам ждёт смены этапа.
6. Проверить проект через `montazhka_inspect`, затем сделать компактный черновик.
7. Если пользователь поручил готовый файл — вызвать финальный `montazhka_export`.
8. Проверить готовый файл через `montazhka_check`, затем отдать его критику (`montazhka://critic`).

## Тринадцать MCP-инструментов

| Инструмент | Назначение |
|---|---|
| `montazhka_doctor` | Проверка движка, модели и папок |
| `montazhka_get_projects` | Список или один проект |
| `montazhka_edit_video` | Полный монтаж по профилю |
| `montazhka_make_shorts` | Черновики-проекты и вертикальные MP4 из моментов, выбранных агентом |
| `montazhka_edit_project` | Точные резы и настройки в копии проекта |
| `montazhka_get_job` | Короткий статус по `jobId`, с `waitSeconds` — ожидание смены этапа |
| `montazhka_inspect` | Лента: клипы с номерами, время ленты и исходника, ревизия, заметки агента `notes`; до 200 клипов, дальше `nextOffset` |
| `montazhka_transcript` | Слова с номерами и временем ленты, паузы, склейки, отпечаток `timeline`; поиск `query`, фразы `phrases`, дубли `retakes`; любой файл через `filePath` |
| `montazhka_frames` | Сетка кадров картинкой: диапазон, точные моменты или «до/после» склеек |
| `montazhka_audio` | Громкость по отрезкам (dBFS) и тишины; у файла ещё громкость LUFS |
| `montazhka_apply_edits` | Правки ленты, исправления расшифровки, оформление черновика шортса, анимации поверх видео и заметки проекта |
| `montazhka_export` | Черновой или финальный MP4 с проверкой длительности, громкостью и `.srt` рядом |
| `montazhka_check` | Проверка готового MP4 у каждой склейки: обрезанные слова, щелчки, провалы, чёрные кадры, скачки громкости |

Большие ответы не входят в обычный вызов. Транскрипт, кандидаты, отчёт и итог
фоновой работы читаются по адресам `montazhka://runs/{jobId}/{artifact}`.
Постоянные ресурсы: `montazhka://guide` — справочник и порядок монтажа, `montazhka://critic` — промпт критика
(раздел «Критик»).

## Профили

- `clean-speech`: длинные паузы, осторожные речевые исправления, улучшение голоса, без музыки.
- `dynamic`: более короткие паузы, те же осторожные смысловые правила.

Точные внешние резы имеют поля `sourcePath`, `start`, `end`. Корректные диапазоны
применяются буквально, без сдвига к словам и тишине.

`aiMode="built-in"` включает встроенный смысловой монтаж.
`aiMode="external"` создаёт копию проекта, возвращает расшифровку и ждёт точные
резы через `montazhka_edit_project`. Если модели ещё нет, агент повторяет вызов с
`confirmModelDownload=true` только после подтверждения.

## Самостоятельный монтаж

Инструменты «глаз, ушей и ножниц» работают во времени ленты проекта — в секундах
итогового ролика. `montazhka_frames` и `montazhka_audio` вместо проекта принимают
`filePath`: так агент проверяет готовый MP4.

- `montazhka_transcript` — строки `#номер начало конец слово`, отметки `--- пауза ---` и
  `--- склейка ---`, до 1500 слов за вызов, продолжение с `nextFrom`, отпечаток ленты `timeline`.
  `query` возвращает до 30 совпадений фразы: номера слов `from`/`to`, время и контекст (регистр,
  «ё» и знаки препинания не важны, слово запроса совпадает с началом слова). Если расшифровки
  ещё нет, вызов запускает её в фоне и возвращает `jobId`.
  - `phrases=true` — вместо строк слов одна строка на фразу: `¶<номер> #<первое>–#<последнее> <начало> <конец> <текст>`
    (время ленты, две цифры после точки). Фраза — слова подряд без паузы от 0,5 с и без склейки. Показываются
    фразы, задетые страницей, целиком; страницы и `nextFrom` считаются по словам, `timeline` тот же.
  - `retakes=true` добавляет `retakes` — вероятные дубли по всей расшифровке, а не только по странице
    (не больше 50 групп):
    `[{"kind": "restart"|"repeat", "similarity": 0.83, "takes": [{"phrase": 12, "from": 340, "to": 361,
    "start": 12.4, "end": 16.9, "text": "…"}]}]`. `restart` — оборванное начало, `repeat` — фраза сказана
    заново; `similarity` — самая слабая связь в группе. Номера с 1: `phrase` — номер строки `¶`, `from`/`to` —
    номера слов, они сразу годятся для `deleteWords`. Какой дубль оставить, решает агент.
  - `filePath` вместо `projectId` (ровно одно из двух, иначе `INVALID_INPUT`) — расшифровка любого файла во
    времени файла: тот же формат строк, страницы и `nextFrom`, отметки пауз, без склеек и без `timeline`;
    в ответе `"timeBase": "file"`, номера слов в `retakes` относятся к словам файла. Нет расшифровки в кэше —
    фоновая задача с тем же ответом (`jobId`, `status`), что у проекта, и тот же `MODEL_DOWNLOAD_REQUIRED`.
    Словарь терминов и ручные исправления применяются так же, как у проекта.
- `montazhka_frames` — одна JPEG-сетка до 16 кадров с таймкодами. `from`+`to`+`count`
  дают равномерные кадры (узкий диапазон — приближение), `times` — точные моменты,
  `aroundCuts=true` — пары «до/после» каждой склейки проекта. В MCP картинка приходит
  прямо в ответе, в CLI — путём `imagePath`. Кадры проекта — как в готовом MP4: у обычного проекта
  с анимациями и (если `export.burnSubtitles`) вшитыми субтитрами, у черновика шортса — вертикальный кадр.
- `montazhka_audio` — `levelsDB` по `buckets` равным отрезкам (до 200), `loudestDB`,
  тишины от 0,4 секунды. С `filePath` — ещё `loudness` всего файла: `integratedLUFS`, `truePeakDBTP`,
  `loudnessRangeLU`, `targetLUFS` (−14); `null`, если в файле нет звука.
- `montazhka_apply_edits` — операции выполняются по порядку:

| Операция | Поля | Что делает |
|---|---|---|
| `deleteWords` | `words[{from,to}]`, `timeline` | Вырезает слова по номерам из `transcript`; рез ложится в тишину между словами. `timeline` должен совпадать с текущей лентой |
| `delete` | `ranges[{from,to}]` | Вырезает куски; все диапазоны считаются по ленте до операции |
| `split` | `at` | Разрезает клип в точке |
| `move` | `clip`, `to` | Переставляет клип на новое место (номера из `inspect`) |
| `trim` | `clip`, `edge` (`start`/`end`), `seconds` | Подрезает край; отрицательное число удлиняет в пределах исходника |
| `insert` | `sourcePath`, `start`, `end`, `at` | Вставляет кусок любого исходника (время файла) в точку ленты |
| `fixWords` | `words[{from,to}]`, `timeline`, `text`, `remember` | Исправляет распознанный текст: слова становятся одним словом `text`, номера не сдвигаются; `remember` дописывает замену в словарь `glossary.json` |
| `setHook` | `text` | Черновик шортса: текст хука (пусто — без хука) |
| `setLayout` | `layout` (`face`/`split`/`fit`) | Черновик: кадр за лицом, экран сверху + лицо снизу, кадр целиком |
| `setSubtitles` | `on` | Черновик: субтитры в стиле из настроек приложения. Обычный проект: вшивать фразы в кадр при экспорте (`export.burnSubtitles`) |
| `zoom` | `words[{from,to}]`, `timeline` | Черновик: плавный наезд на слова |
| `clearZooms` | — | Черновик: убрать все наезды |
| `setMusic` | `track` (id или `none`), `volume` | Черновик: сменить или убрать музыку |
| `addOverlay` | `file`, `words[{from,to}]`+`timeline` или `at`, `align`, `payoffAt`, `position`, `scale` | Обычный проект: анимация поверх видео (см. «Анимации поверх видео») |
| `removeOverlay` | `overlay` | Убирает анимацию по `id` из `overlays` |
| `clearOverlays` | — | Убирает все анимации |
| `note` | `text` | Дописывает заметку проекта под заголовком с датой (см. «Заметки проекта») |
| `setNotes` | `text` | Переписывает заметки целиком; пустой `text` очищает их |
| `undo` | `steps` | Отдельным вызовом возвращает предыдущую ревизию (оформление тоже) |

Каждая правка сохраняет ревизию в `~/Library/Application Support/Montazhka/AgentRevisions`.
Ответ содержит новую ленту (до 50 клипов, `clipsShown`) и предупреждения: рез посреди слова,
новый кусок короче 0,25 секунды. После любой правки номера слов и клипов меняются — перед
следующим `deleteWords` снова вызовите `transcript`.

Если проект открыт в окне Монтажки, окно подхватывает правку агента в течение секунды и
показывает «Агент изменил проект»; пользователь может вернуть прежнюю версию. Окно больше
не перезаписывает файл, который изменил агент.

Порядок работы: `edit_video` → `inspect` → `transcript` → `frames`/`audio` в сомнительных
местах → `apply_edits` → `frames aroundCuts=true` → финальный `export` → `check` готового
файла → критик. Старый сервер без `montazhka_check` — `frames projectId filePath aroundCuts=true`.

## Экспорт

`montazhka_export` — фоновая задача; итог в `montazhka_get_job` (`result`) и в ответе CLI.

- `normalizeLoudness` (без поля — как в проекте, по умолчанию включено): звук приводится к −14 LUFS, пик не
  выше −1 dBTP. `false` — оставить громкость как есть. CLI: `--no-normalize-loudness`.
- `burnSubtitles` (без поля — как в проекте, по умолчанию выключено): фразы впечатываются в кадр обычного
  проекта (у черновика шортса свои субтитры). Включить для проекта насовсем — `setSubtitles{on}` в
  `apply_edits`. CLI: `--burn-subtitles`.
- В итоге: `path`, `durationCheck`, `loudness` (`integratedLUFS`, `truePeakDBTP`, `loudnessRangeLU`,
  `normalized`, `gainDB`, `targetLUFS`, `targetMet`), `subtitlesPath` — `.srt` рядом с MP4 (ложится всегда,
  когда есть расшифровка), `subtitlesSkippedReason` — почему `.srt` нет, `warnings` сборки и записи.
  У финального файла ещё `nextSteps`: `montazhka_check` и критик.
- В метаданных MP4 лежит отпечаток ленты — по нему `montazhka_check` узнаёт, свежий ли файл.

## Проверка готового файла

`montazhka_check` — только чтение. Вход: `projectId` (обязательно), `filePath` (по умолчанию MP4 черновика
шортса; у обычного проекта без него — `INVALID_INPUT`), `from`/`to` (секунды ленты), `window` (секунды по
каждую сторону склейки, по умолчанию 1,5), `words` (по умолчанию `true`), `confirmModelDownload`.

- Сверка файла с проектом: отпечаток ленты в файле совпал — `"match": "confirmed"`; отпечаток другой —
  ошибка `FILE_PROJECT_MISMATCH` «Файл собран из старой ленты — экспортируйте заново»; отпечатка нет —
  длительности должны сойтись до 0,25 с (иначе та же ошибка), `"match": "unconfirmed"`.
- Склейки — начала клипов после первого, до 40 за вызов; остальные — повтором с `from=nextFrom`.
  `cutCount` — сколько склеек в диапазоне.
- `cuts[]`: `time`, `audio` (`clickRatio`, `click`, `dropoutMs`, `levelJumpDB` — громкость до минус после),
  `video` (`lumaBefore`, `lumaAfter` за 0,08 с до и через 0,04 с после, `black`), `words` (`expected` — слова
  ленты в окне, `heard` — слова, распознанные в файле, `missing`, `suspect` — пропало слово у самой склейки),
  `problems` — виды проблем этой склейки. Нет звуковой или видеодорожки — соответствующее поле `null`.
- `problems[]`: `{time, kind, evidence}`, по важности: `cutWord`, `click`, `dropout`, `black`, `levelJump`
  (скачок — только от 10 дБ). Это подсказки с уликами: смотрите кадры и слушайте место сами.
- `wordsCheck`: `done`; `pending` с `jobId` — расшифровка файла запущена в фоне, дождитесь её и вызовите
  `check` снова; `off` с `reason` — `words=false`, нет расшифровки проекта или нужна модель
  (повторите с `confirmModelDownload=true`).
- `loudness` файла (как у `montazhka_audio`), `imagePath` — сетка «до/после» для 8 склеек, проблемные первыми
  (в MCP картинка приходит в ответе), `fileSeconds`, `projectSeconds`, `window`, `filePath`.

## Критик

Ресурс `montazhka://critic` (CLI: `critic-prompt` → `{"text": …}`) — промпт строгого редактора. После финального
экспорта и своего `montazhka_check` агент подставляет `{{filePath}}`, `{{projectId}}`, `{{brief}}` (бриф
пользователя дословно) и `{{notes}}` и запускает критика отдельным субагентом со свежим контекстом (в Codex —
отдельной сессией `codex exec`, если субагент не видит MCP). Критик только читает и отвечает `VERDICT` (ship /
fix / rework), `ISSUES` и `TOP-5 FIXES`. Технические проблемы агент чинит сам, перевыгружает (`overwrite=true`)
и зовёт нового критика; вердикт `ship` или три круга — конец. Вкусовые замечания агент показывает пользователю
списком вместе с путём к файлу.

## Анимации поверх видео

Только обычный проект (у черновика шортса — ошибка «Анимации пока только в обычном проекте»). Файл — прозрачный
ProRes 4444 (`npx hyperframes render --format mov --fps 30`, 60 для видео 60 к/с), 0,2–60 с; webm не читается.
Размер композиции — `frameSize` из `inspect`.

- `addOverlay`: `file`; якорь — `words[{from,to}]` со свежим `timeline` (начало слова `from`) или `at`
  (секунды ленты; при расшифровке якорь встаёт на начало слова под этим моментом). `align`: `payoff` —
  секунда `payoffAt` анимации совпадёт с якорем (без `align`, но с `payoffAt` — тоже payoff), `start` —
  анимация начнётся с якоря. `position`: `full` (по умолчанию) — вписана в кадр целиком, `scale` не
  учитывается; `center`, `topLeft`, `topRight`, `bottomLeft`, `bottomRight` — уменьшена в `scale` раз
  (0.2…1), отступ 4% от краёв кадра. Файл проверяется (прозрачность, длина; другие пропорции — предупреждение)
  и подготовленной копией ложится в папку `Overlays` данных приложения; в проект идёт копия.
- Анимация держится за момент исходника: правки ленты двигают её вместе со словом. Слово вырезано — анимация
  скрыта, в `warnings` ответа: «Анимация <id> («<слово>»): слово вырезано — анимация скрыта; removeOverlay или
  addOverlay заново». Момент якоря повторяется на ленте — тоже предупреждение, анимация встаёт у первого.
- `undo` откатывает и анимации.
- `inspect` и ответ `apply_edits` обычного проекта: `frameSize {width, height}` и `overlays[]`: `id`, `file`
  (подготовленная копия), `word`, `timelineStart`/`timelineEnd` (окно на ленте; `null`, если не видна),
  `payoffTimeline` (где кульминация на ленте, только у `payoff`), `position`, `status` (`visible`,
  `anchorCut` — слово вырезано, `tooShort` — окно короче 0,1 с).

## Заметки проекта

Заметки — память агента о проекте между сессиями: бриф пользователя, стратегия, решения, просьбы, что
осталось. Пользователь их не видит. Они лежат вне проекта, в
`~/Library/Application Support/Montazhka/AgentNotes/<projectId>.md`, поэтому окно Монтажки их не трогает.

- `montazhka_inspect` возвращает `"notes"`: текст или `null`, если заметок нет.
- `note{text}` дописывает заметку под заголовком `## гггг-ММ-дд ЧЧ:мм`; `setNotes{text}` переписывает всё
  (пустой `text` очищает). Лимит — 20 000 знаков: длиннее запись отклоняется с просьбой сжать через `setNotes`.
- Пачка только из заметок не трогает ленту: без ревизии, без сохранения проекта и без баннера в окне, работает
  и с недоступными исходниками. Ответ — обычный ответ `apply_edits` плюс `"notesSaved": true`.
- В смешанной пачке правки ленты выполняются и сохраняются как обычно, затем пишутся заметки. Если заметку
  записать не удалось, правка остаётся, ответ успешный: `"notesSaved": false` и предупреждение
  «Заметка не записана: …» в `warnings`.
- `undo` заметки не откатывает. Копия проекта (`edit_project`) получает копию заметок под заголовком
  «Копия проекта «<имя>» (<id>)».

## Шортсы и Reels

Моменты выбирает агент — встроенный платный отбор приложения не вызывается. Порядок и критерии
отбора описаны в ресурсе `montazhka://guide`. Кратко: расшифровка → кандидаты по критериям
hook/standalone/payoff/pacing → таблица пользователю и вопрос о субтитрах → `montazhka_make_shorts`.

```json
{"projectId": "…", "timeline": "…", "shorts": [{"title": "Как я монтирую", "hook": "Монтаж за минуту",
  "subtitles": false, "pieces": [{"from": 120, "to": 190}], "layout": "auto", "mood": "energetic"}]}
```

- `pieces` — слова `{from,to}` из `montazhka_transcript` или секунды ленты `{start,end}`, в порядке показа.
- `layout`: `face` — кадр 9:16 ведёт лицо (Apple Vision, локально); `split` — экран целиком сверху,
  лицо снизу; `fit` — кадр целиком; `auto` — по лицам в кадре.
- `zooms` не передан — плавные наезды подбираются сами; `[]` — без наездов.
- `music` — id трека из `montazhka_doctor.music`, `none` или по `mood`; музыка стихает под речью.
- Паузы и «звук без слов» (скорее всего «эээ») вырезаются сами (`trimPauses`, `removeFillers`).
- Каждый ролик — проект-черновик и MP4 в папке «<исходник>-shorts». `montazhka_frames` черновика
  показывает вертикальный результат с хуком и субтитрами; `montazhka_export` перевыгружает его файл.
- `montazhka_inspect` и ответ `apply_edits` черновика содержат блок `shorts`: хук, раскладка, субтитры,
  наезды во времени ленты, музыка и путь MP4. Копия черновика (`edit_project`) получает свой путь MP4.
- Заметки черновика: «Черновик шортса «<заголовок>» из проекта <id>. Общие заметки — в нём. Хук: <хук>».
- `montazhka_check projectId` черновика без `filePath` проверяет его MP4.

## CLI

CLI возвращает один JSON-объект версии 1 в stdout. Диагностика: `montazhka doctor`.
Основные команды: `projects`, `edit-video`, `edit-project`, `make-shorts`, `job`,
`inspect`, `transcript`, `frames`, `audio`, `apply-edits`, `export`, `check`, `critic-prompt`, `integration`.
Проверка файла: `check --project <id> --file <mp4> --from --to --window --no-words --confirm-model-download`.
Экспорт: `--no-normalize-loudness`, `--burn-subtitles`.
Кадры и звук: `--project <id>` или `--file <mp4>`, `--from`, `--to`, `--count`,
`--times 1.5,3`, `--around-cuts`, `--buckets`. Расшифровка: `transcript --project <id>` или `--file <путь>`,
`--phrases`, `--retakes`; поиск — `transcript --query "фраза"`,
ожидание задачи — `job --id <jobId> --wait 25`, шортсы — `make-shorts --request shorts.json`, страницы ленты — `inspect --offset 200 --limit 200`. Правки: `montazhka apply-edits --project <id>
--request ops.json` (список операций или `{"operations": [...]}`), отмена — `--undo [шаги]`. Для сложного пакета: `montazhka edit-project --request request.json`.
Во встроенном ИИ через CLI используется `--smart-edit`, во внешнем — `--external-ai`.

Существующий выходной файл сохраняется. Перезапись возможна только с явным
`--overwrite`. Финальный экспорт требует одновременно `--final --confirm-final`;
просьба пользователя «смонтируй и сделай готовый файл» — достаточное согласие.
Без `outputPath` финал ложится рядом с исходником как `<имя>-montazhka.mp4`,
черновик — как `<имя>-montazhka-draft.mp4`. Итог экспорта содержит `durationCheck`.

## Версия сервера

`montazhka_doctor` возвращает `version` (версия, сборка, коммит) и `serverStale`. Сервер MCP живёт
столько же, сколько сессия агента. Если приложение переустановили после её старта, каждый ответ
содержит `warnings` с просьбой перезапустить сессию: до этого агенту видны старые инструменты.
При запуске приложение само обновляет скилл `montazhka` у подключённых агентов.

## Восстановление

Состояние хранится в `~/Library/Application Support/Montazhka/AgentRuns`.
После закрытия агента новый сеанс продолжает проверку по тому же `jobId`.
Ошибка содержит код, понятное сообщение и, когда возможно, способ восстановления.

Если модели нет, умный монтаж и shorts возвращают `MODEL_DOWNLOAD_REQUIRED` и примерный размер.
Повторный вызов с `confirmModelDownload=true` разрешает загрузку. Совместимая
Parakeet Core ML-модель в известной папке используется на месте.

## Обязательная проверка результата

- Все исходники доступны.
- Длительность и дорожки распознаны.
- Точные резы входят в исходники.
- Кадры «до/после» склеек просмотрены через `montazhka_frames aroundCuts=true`.
- Финальный MP4 существует, `durationCheck.matches` равно `true`.
- Кадры и громкость готового MP4 проверены через `filePath`.
- `montazhka_check` готового MP4 разобран: каждая запись `problems` проверена или исправлена.
- Критик (`montazhka://critic`) отработал: вердикт `ship` или три круга, вкусовые замечания показаны пользователю.
- Исходные видео не изменились.
