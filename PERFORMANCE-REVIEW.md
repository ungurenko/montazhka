# ⚡ Ревью производительности: Монтажка

**Дата:** 2026-07-05
**Что за проект:** десктоп-приложение для macOS на Swift/SwiftUI + AVFoundation, размер S (~2800 строк). Профиль ДЕСКТОП.
**Как проверял:** замерил сборку и самопроверку (весь конвейер: волна → поиск пауз → склейка → экспорт MP4 на тестовом видео 12 сек — 0,75 сек, все 16 проверок прошли) · отзывчивость интерфейса при большом числе клипов вывел из кода — окно без человека не покликать.
**Статус плана:** все пункты 1–6 закрыты (1, 2, 4, 5 — 2026-07-06; 3 и 6 — 2026-08-25)

## 📊 Общий вердикт

🟢 **В целом хорошо.** На обычном материале (несколько клипов) монтажка быстрая, движок здоров,
утечек памяти не видно. Слабое место одно, но оно на самом горячем пути: **после каждой правки
(разрез, удаление, вырезка пауз, отмена) предпросмотр пересобирается с нуля и по очереди** —
чем больше клипов на ленте (а после вырезки 50 пауз их становится ~100), тем дольше пауза после
каждого действия. Плюс перемотка мышью по ленте может отставать от курсора.

## 🐌 Что тормозит (главные находки)

### 1. Каждая правка пересобирает весь предпросмотр с нуля, и по очереди
- **Что тормозит:** после разреза, удаления, вырезки пауз или отмены плеер собирает склейку
  заново: для каждого клипа заново открывается исходный файл и по очереди (не параллельно)
  загружаются видео- и аудиодорожки — 2 ожидания × число клипов.
- **Где:** `Sources/Montazhka/Engine/CompositionBuilder.swift:16-33` (вызывается из
  `EditorController.rebuildAndSeek`, срабатывает на каждой правке).
- **Чем грозит:** с 5 клипами незаметно; после вырезки 50 пауз клипов ~100 — и каждая
  следующая правка отвечает с ощутимой задержкой. Чем длиннее монтаж, тем хуже.
- **Подтверждение:** 🔍 выведено из кода.

### 2. Перемотка мышью по ленте отстаёт от курсора
- **Что тормозит:** при протяжке по линейке каждый сдвиг мыши шлёт плееру команду «перемотай
  точно на этот кадр» (точная перемотка = дорогая распаковка видео). Команды копятся быстрее,
  чем плеер их выполняет, — картинка догоняет мышь с запаздыванием.
- **Где:** `Sources/Montazhka/Views/TimelineView.swift:154-160` →
  `Sources/Montazhka/Engine/EditorController.swift:148-154`.
- **Чем грозит:** «ватная» перемотка на длинных и тяжёлых (4K) исходниках.
- **Подтверждение:** 🔍 выведено из кода (штатное лекарство — не слать новую перемотку, пока
  не закончилась предыдущая).

### 3. Лента пересчитывает позиции всех клипов 30 раз в секунду
- **Что тормозит:** во время воспроизведения время курсора обновляется 30 раз/сек и каждый раз
  перестраивает всю ленту; при этом позиция каждого клипа считается заново перебором всех
  предыдущих (для 100 клипов — ~10 000 лишних операций на каждое обновление, 30 раз/сек).
- **Где:** `Sources/Montazhka/Views/TimelineView.swift:106-107` (`firstIndex` + `timelineStart`
  на каждый клип в цикле отрисовки).
- **Чем грозит:** подъедает процессор и плавность во время воспроизведения при десятках клипов;
  на коротких проектах незаметно.
- **Подтверждение:** 🔍 выведено из кода.

### 4. Первый поиск пауз обсчитывает файлы по очереди
- **Что тормозит:** перед поиском пауз волны звука для каждого файла считаются последовательно,
  хотя могли бы параллельно (обсчёт = распаковка всего звука файла).
- **Где:** `Sources/Montazhka/Engine/EditorController.swift:307-311`.
- **Чем грозит:** только первый запуск на новых файлах ждёт дольше нужного; повторные — из кэша
  мгновенно. 📏 Замерено: на тестовом видео 12 сек волна+поиск заняли доли секунды, узкое место
  проявится на нескольких длинных файлах сразу.
- **Подтверждение:** 🔍 выведено из кода + 📏 частично замерено.

### 5. Добавление клипов читает длительности по очереди
- **Что тормозит:** при добавлении нескольких видео их длительности читаются последовательно —
  добавил 10 файлов, ждёшь сумму всех чтений вместо самого долгого.
- **Где:** `Sources/Montazhka/Engine/EditorController.swift:213-227`.
- **Чем грозит:** лишняя пауза после выбора файлов; на 2-3 файлах незаметно.
- **Подтверждение:** 🔍 выведено из кода.

### 6. Мелочи на холодных путях (не критично)
- Проверка «файлы на месте?» при открытии проекта идёт на главном потоке
  (`EditorController.swift:84-92`) — на локальном диске мгновенно, на сетевом может подвесить.
- Стартовый экран читает полный файл каждого проекта ради карточки
  (`ProjectStore.swift:42-55`) — заметно станет только при сотнях проектов.
- **Подтверждение:** 🔍 выведено из кода.

## ✅ Что со скоростью хорошо

- Волны звука считаются в фоне и кэшируются на диск с умным ключом (размер + дата файла) —
  повторные открытия проекта мгновенные (`WaveformStore.swift`).
- Ячейки ленты перерисовываются только при реальных изменениях (`.equatable()` в `TimelineView`).
- Автосохранение с задержкой 500 мс и безопасной записью — не дёргает диск на каждый чих.
- Защита от «устаревших» пересборок предпросмотра (`rebuildGeneration`) — быстрые серии правок
  не дерутся друг с другом.
- Память под контролем: отмена ограничена 200 шагами, волны ~1,4 МБ на час видео, наблюдатели
  и монитор клавиатуры корректно снимаются. Утечек не найдено.
- 📏 Замерено: самопроверка (волна → поиск пауз → склейка → экспорт) — 0,75 сек, 16/16 проверок.
